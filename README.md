A working ML system that predicts Diabetes and Heart Disease risk using real
Kaggle/UCI datasets, with a Flask API backend and a web frontend.

## Project Structure
```
disease_prediction/
├── data/
│   ├── diabetes_raw.csv   # Pima Indians Diabetes dataset (768 records, 8 features)
│   └── heart_raw.csv      # UCI Heart Disease dataset (303 records, 13 features)
├── src/
│   ├── preprocess.py      # Module 2: cleaning, missing-value imputation
│   ├── train.py           # Module 3+4+5: feature selection, RF/KNN/LogReg training, evaluation
│   ├── predict.py         # Module 6: integration layer (combined prediction)
│   └── app.py             # Module 7: Flask REST API
├── models/                 # Saved .pkl models, scalers, metrics (generated by train.py)
└── frontend/
    └── index.html          # Module 8: web UI (Diabetes + Heart Disease forms)
```

## How to run

### 1. Install dependencies
```bash
pip install pandas scikit-learn joblib flask flask-cors
```

### 2. Train the models (creates /models/*.pkl)
```bash
cd src
python3 train.py
```

### 3. Start the API
```bash
python3 app.py
# Runs on http://localhost:5000
```

### 4. Run the frontend
Two frontends are included:

- **`frontend/index.html`** — a static, dependency-free HTML/CSS/JS version.
  Open it directly in a browser or serve it with `python3 -m http.server`
  from the `frontend/` folder.
- **`frontend-react/`** — the React + Vite + Tailwind version from the Figma
  Make export ("Vitalign Clinical Dashboard"), wired to the same Flask API.
  ```bash
  cd frontend-react
  npm install
  npm run dev
  # opens on http://localhost:5173
  ```

Both call the Flask API at `http://localhost:5000`, so make sure `app.py` is
running first (see step 3). If you deploy the API somewhere other than
localhost, update `API_BASE` in `frontend-react/src/App.tsx`.

## Datasets used (real, from Kaggle/UCI)
- **Diabetes**: Pima Indians Diabetes Dataset — 768 patients, 8 clinical features
  (Glucose, BMI, Blood Pressure, Insulin, etc.), binary outcome.
- **Heart Disease**: UCI Heart Disease Dataset (Cleveland) — 303 patients,
  13 clinical features (age, cp, thalach, oldpeak, etc.), binary target.

## Algorithms compared (Module 4)
For each disease, three algorithms are trained and compared on the same
70% train / 30% test split (stratified):
- **Random Forest Classifier**
- **K-Nearest Neighbors (KNN)**
- **Logistic Regression** (baseline)

The best model per disease is auto-selected by **F1-score** (balances
precision/recall — important for medical risk prediction where both false
positives and false negatives matter) and saved to `/models`.

### Results from this run
| Disease | Best Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| Diabetes | KNN | 0.745 | 0.662 | 0.556 | 0.604 |
| Heart Disease | KNN | 0.802 | 0.782 | 0.878 | 0.827 |

Diabetes prediction is a harder problem given this dataset's size and noise —
that's expected and worth stating honestly in your viva rather than inflating
the numbers.

## Figma integration
`frontend-react/` is the React export from the "Vitalign Clinical Dashboard"
Figma Make file, integrated with the real backend:
- Field names were mapped from the form's camelCase keys (e.g. `bloodPressure`)
  to the exact keys `predict.py` / `models/*_meta.json` expect (e.g.
  `BloodPressure`).
- The mock `computeRisk()` function from the Figma export was replaced with a
  real `fetch` call to `/predict/diabetes` and `/predict/heart`.
- Response fields (`risk_probability`, `prediction`, `model_used`) are mapped
  into the UI's gauge, verdict badge, and result table.
- Figma-Make-only build plugins (site.json config, HMR replay, kit.html) were
  stripped from `vite.config.ts` since they only matter inside Figma's own
  preview environment.
- Added an error state for when the Flask API isn't running or returns an
  error, so the UI doesn't hang or look broken.
