## Abstract

This project presents a machine learning system that predicts an
individual's risk of **Diabetes** and **Heart Disease** using two
real, publicly available clinical datasets — the Pima Indians Diabetes
Database (768 patients) and the UCI Cleveland Heart Disease dataset
(303 patients). Three classification algorithms — Random Forest,
K-Nearest Neighbors (KNN), and Logistic Regression — were trained and
compared per disease on a stratified 70/30 train-test split. The
best-performing model for each disease (selected by F1-score) was
deployed behind a Flask REST API and connected to a clinical-style web
dashboard, allowing a user to enter patient measurements and receive an
instant risk probability, verdict, and model explanation. The system
achieved 74.5% accuracy (F1 = 0.604) for diabetes and 80.2% accuracy
(F1 = 0.827) for heart disease, with KNN selected as the best model for
both diseases.

## Introduction

Chronic conditions like diabetes and heart disease are leading causes
of preventable illness, and early risk screening can meaningfully
improve outcomes. Manual risk assessment relies on a clinician
interpreting several correlated lab values at once — a task well
suited to supervised machine learning. This project builds an
end-to-end pipeline: real clinical data → preprocessing → model
training/comparison → a deployed prediction API → an interactive web
front end, so a user can input patient vitals and get an immediate,
model-backed risk estimate rather than a static computed score.

## Methods and Materials

**Datasets** (see References for sources):
- **Diabetes** — Pima Indians Diabetes Database: 768 female patients,
  8 clinical features (Pregnancies, Glucose, Blood Pressure, Skin
  Thickness, Insulin, BMI, Diabetes Pedigree Function, Age), binary
  outcome.
- **Heart Disease** — UCI Cleveland Heart Disease dataset: 303
  patients, 13 clinical features (age, sex, chest pain type, resting
  BP, cholesterol, fasting blood sugar, resting ECG, max heart rate,
  exercise-induced angina, ST depression, ST slope, major vessels,
  thalassemia), binary target.

**Preprocessing:**
- Diabetes: physiologically impossible zero-values in Glucose, Blood
  Pressure, Skin Thickness, Insulin, and BMI were treated as missing
  and imputed with the column median (robust to outliers); duplicate
  rows removed.
- Heart disease: duplicate and incomplete rows removed.
- Both datasets were feature-scaled with `StandardScaler`, fit on the
  training split only to prevent data leakage.

**Feature selection:** a Random Forest importance scan (200 trees)
ranked feature contribution per disease — Glucose, BMI, and Age were
the strongest diabetes predictors; chest pain type, max heart rate, and
number of major vessels were the strongest heart disease predictors.

**Model building:** for each disease, three algorithms were trained on
a stratified 70% train / 30% test split (`random_state=42`):
- Random Forest Classifier (300 trees, max depth 8)
- K-Nearest Neighbors (k = 9)
- Logistic Regression (baseline, max 1000 iterations)

**Model selection:** the best model per disease was chosen by
**F1-score** — the balance of precision and recall — since both false
positives and false negatives carry real cost in medical screening.

**Deployment:** the selected model, its scaler, and its feature order
were serialized (`joblib`) and served through a Flask REST API
(`/predict/diabetes`, `/predict/heart`) with CORS enabled, called by a
React + Tailwind clinical dashboard front end.

## Results

| Disease | Best Model | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|---|
| Diabetes | KNN | 0.745 | 0.662 | 0.556 | 0.604 |
| Heart Disease | KNN | 0.802 | 0.782 | 0.878 | 0.827 |

**Confusion matrices** (`models/diabetes_confusion_matrix.png`,
`models/heart_confusion_matrix.png` — generated by `src/visualize.py`):

- **Diabetes (KNN):** of 231 test patients, 127 true negatives and 45
  true positives were classified correctly; 23 were false positives
  (predicted diabetic but weren't) and 36 were false negatives
  (predicted healthy but were diabetic) — the higher false-negative
  count is the main driver of the lower recall (0.556).
- **Heart Disease (KNN):** of 91 test patients, 30 true negatives and
  43 true positives were classified correctly; 12 false positives and
  only 6 false negatives — the low false-negative count explains the
  strong recall (0.878), which matters clinically since missing an
  at-risk heart patient is costlier than a false alarm.

**ROC curves** (`models/diabetes_roc_curve.png`, `models/heart_roc_curve.png`
— generated by `src/visualize.py`, computed on the same held-out test split):

- **Diabetes (KNN): AUC = 0.814** — the model separates diabetic from
  non-diabetic patients well above chance (AUC 0.5 = random guessing);
  0.8+ is generally considered "good" discrimination in medical ML.
- **Heart Disease (KNN): AUC = 0.866** — stronger separation than
  diabetes, consistent with its higher accuracy/F1 above.

**Top predictive features (by Random Forest importance):**
- Diabetes: Glucose (0.256), BMI (0.166), Age (0.132), Diabetes
  Pedigree Function (0.124)
- Heart Disease: Chest Pain Type (0.137), Max Heart Rate (0.125),
  Major Vessels (0.110), Thalassemia (0.108)

KNN outperformed Random Forest and Logistic Regression on F1-score for
both diseases, indicating that local-neighborhood similarity in the
scaled feature space captured risk patterns slightly better than
either a tree ensemble or a linear boundary on these particular
datasets.

## Discussion

Heart disease prediction (F1 = 0.827) substantially outperformed
diabetes prediction (F1 = 0.604). This gap is consistent with the
datasets themselves rather than a modeling flaw: the diabetes dataset
is smaller in useful signal (many zero-imputed values before cleaning)
and its features are noisier proxies for the underlying condition,
while the Cleveland heart dataset's features (chest pain type, ST
depression, vessel count) are more directly diagnostic. This is worth
stating plainly in a viva rather than presenting inflated numbers —
the honest limitation is part of the analysis. A secondary
consideration is class imbalance: diabetes-positive cases are a
minority in the Pima dataset, which tends to depress recall for the
positive class, visible in the diabetes confusion matrix.

## Conclusions

A complete, working pipeline was built from raw real-world clinical
data to a live, queryable prediction system. Both disease models
perform meaningfully above chance and above a naive baseline, with
heart disease prediction reaching strong (>80%) accuracy and F1. The
project demonstrates that (1) simple, well-understood algorithms (KNN)
can outperform more complex ones (Random Forest) on small, cleanly
separable medical datasets; (2) feature importance analysis surfaces
clinically sensible predictors (glucose for diabetes, chest pain type
for heart disease), lending interpretability alongside accuracy; and
(3) a full deployment loop (model → API → UI) is achievable end-to-end
in a single course project. Future work could improve diabetes recall
with class-balancing techniques (SMOTE) or ensemble stacking across
all three trained algorithms rather than selecting only the single
best.
